# PRD — 对抗式审查

## Goal

Phase 11 后独立任务：**假设系统一定有缺陷**，围绕五个方向构造用例并实际运行：
1. 卡余额并发（多协程同时核销/调整/作废同一张卡）
2. 预约冲突（并发/边界时段/改期竞争）
3. 核销幂等（重放/异键/撤销后重入）
4. 撤销重入（重复撤销/撤销与核销并发/撤销后余额）
5. 权限越界（顾客读他人预约/卡/资料，顾客调用后台端点）

## Requirements

- 审查+用例由**子代理**执行（主会话汇总）
- 用例必须真实运行（go test），不得只做静态推演
- 每个缺陷分级 BLOCKER/WARNING，附复现用例
- BLOCKER 立即修复并重跑全部 E2E
- 结果写入 `.trellis/tasks/对抗审查结果.md`（用户指定路径）

## Acceptance Criteria

- [ ] 对抗审查结果.md 存在且含用例运行证据
- [ ] BLOCKER=0（或已修复并复验）
- [ ] go build/vet/test 全过
