# V2.2 第三批：服务记录与散客快速结算

## Goal

plan §四/§五/§六 落地：服务标签管理（调理部位/服务方式两组，添加/停用/排序/仅未使用可删）、服务记录（核销与结算时采集：部位≤3 多选、方式单选、技师备注+快捷短语、商家备注独立追加、服务前沟通确认勾选）、核销撤销联动记录作废、会员详情「服务追踪」（倒序+筛选+关键词+汇总）、散客快速结算（无预约无卡，手机号可选，现金/微信/其他收款）。

## 范围（源 plan §四/§五/§六 原文要点）

- §四.1-3：核销/结算前三个**选填**项——实际调理部位（多选≤3，默认肩颈/腰背/腿部/足底/全身/其他）、服务方式（单选，默认按摩/针灸/拔罐/刮痧/艾灸/仪器/膏药/其他）、技师备注（输入框+快捷短语，短语由「服务标签管理」统一配置存 settings KV）。全部选填不阻断核销。
- §四.4 散客：未预约到店同样可填三字段；**录手机号 → 自动匹配/创建会员档案 + 服务记录归档；不录手机号 → 仅完成记账收款，不生成服务记录与会员档案**。
- §四.5 撤销：核销撤销时对应服务记录同步作废，不计入汇总。
- §四.6 安全确认：核销页勾选「服务前已完成沟通」，**强制勾选**（默认不勾），不做医疗化措辞（不出现"已确认无禁忌"）。
- §五 标签管理：两组独立（调理部位 BODY_PART / 服务方式 METHOD）；添加/停用/排序；删除仅限从未被使用；停用标签在核销录入页隐藏、在历史筛选器仍可见可筛；历史记录存快照不受标签增删影响。会员标签系统不动、两者不混淆；服务记录/标签均为商家内部数据，用户端不可见。
- §六 服务追踪：会员详情按时间倒序，部位/方式/时间（近1月/近3月/全部）筛选 + 关键词搜备注；技师备注与商家备注独立展示、各记操作人与时间；汇总 = 近3个月共 N 次 + 部位次数 + 方式次数（不做治疗报告/下一阶段方案）。
- 新增散客快速结算（用户确认）：无预约无卡，手机号可选，现金/微信/其他收款 + 服务记录；不做在线支付。

## 用户决策（已确认）

- 技师即店主一人，不做技师独立账号/技师端；"技师备注"由核销操作人（店长本人）在后台代填。
- 散客快速结算本期新增（含"不录手机号仅记账"形态）。

## Acceptance Criteria（Murphy live + 单测）

- [ ] 标签 CRUD：同组同名添加 409；停用后核销录入接口不返回但历史筛选可见；删除被使用标签 409、未使用可删。
- [ ] 预约卡核销 / 直接卡核销 / 现金·微信结算 / 散客快速结算：同事务生成 service_record（服务名快照、部位 JSON ≤3、方式快照、技师备注）；未勾「服务前已完成沟通」→ 拒绝。
- [ ] 核销撤销：同事务 record → REVERSED + 原 payment → VOIDED，汇总不再计数；撤销后重新核销生成新记录。
- [ ] 散客快速结算：录手机号 → 匹配或创建 member + payment + record；不录手机号 → 仅 payment（member_id NULL）无 record；CARD 方式拒绝；幂等键重放不重复扣账。
- [ ] 散客记录独立撤销（非卡）：record REVERSED + payment VOIDED 同事务；卡核销记录走该入口时拒绝（须走 redemption reverse 以还次数）。
- [ ] 服务追踪接口：倒序、部位/方式/时间筛选、关键词命中备注、汇总 counts 正确（REVERSED 不计）。
- [ ] 快捷短语 settings KV `service_note_presets`：服务端校验（字符串数组 ≤20、单项 1..50），脏值不下发。
- [ ] migration 015：payment 重建后历史行保留、valid_lock/idempotency 唯一约束与触发器不失效、外键仍强制。
- [ ] `go build ./... && go vet ./... && go test ./...` 全绿；admin 前端 build 通过。
