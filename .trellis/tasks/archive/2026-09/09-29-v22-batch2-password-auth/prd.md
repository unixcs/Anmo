# PRD — V2.2 第二批：H5 手机号+密码登录体系（短信下线）

来源：`docs/2026929plan.md` §二（账号体系）、§三（资料完善的数据面）。
已拍板：H5 切手机号+密码，短信验证码登录下线；微信手机号快速验证不做；密码连续错误锁定不做。

## R1 账号数据面

1. `member` 表支持密码与"仅微信"账号：新增 `password_hash`（可空）；`phone` 改为可空（未填手机号的纯微信会员），非空仍全局唯一；`wx_openid` 语义不变（可空唯一）。存量数据完整保留（含 wx_openid），走**只增不改**的 migration（SQLite 重建表）。
2. 密码 bcrypt 哈希（与商家后台同款），明文永不落库/落日志。

验收：
- [ ] 迁移在全量 schema 上可重复应用成功；旧 member 数据（含 wx_openid、无密码）无损
- [ ] 两个纯微信会员（phone NULL）并存不触发唯一冲突；非空 phone 重复仍被拒

## R2 H5 手机号+密码

1. **注册**：手机号不存在 → 创建会员（手机号+密码）并登录。手机号已存在 → 不允许重复创建：已设密码提示"该手机号已注册，请直接登录"；已绑定微信且未设密码提示"该手机号已开通微信账号，请前往小程序「我的」设置 H5 密码后登录"（plan §二.4 口径，不自动创建新账号）。
2. **登录**：手机号+密码。密码错误提示"密码错误，请重新输入"；未注册提示"该手机号尚未注册"；**存量无密码账号**（原短信时代会员）提示联系商家重置、已用微信则可在小程序设置 H5 密码。
3. 移除验证码登录 UI（发送/倒计时/输入框）；"忘记密码"引导文案：联系商家后台重置。

验收：
- [ ] 注册→登出→登录→改密→重登全链可用
- [ ] 四类异常提示各自正确（已注册/微信账号/密码错误/未注册/无密码）
- [ ] 旧短信端点在生产 `off` 模式下返回"已下线"提示（见 R5）

## R3 小程序纯微信登录

1. 微信静默登录为唯一登录方式：openid 未绑定 → **直接创建会员**（无手机号、无姓名）并签发顾客 Token，不再返回 bind_ticket（原 D25 绑定票据流程废除）。
2. 同一 openid 再次登录返回同一会员（不重复建号）。
3. 登录页移除短信表单；静默失败（网络/非微信环境）显示重试入口。
4. 新会员资料完善（R4）引导补姓名+手机号；预约不强制资料（沿用第一批半屏提示）。

验收：
- [ ] dev openid 首登建号、二登同号；token 可正常预约
- [ ] 登录页无短信痕迹，静默成功直接进入

## R4 手机号完善与撞号认领（小程序）

1. 新会员在「我的」完善手机号：服务端校验手机号未被占用 → 写入本会员（一次性：已有手机号不允许改）。
2. 手机号已被占用（H5 老账号）→ 提示输入**该手机号的 H5 密码**，验证通过后把当前微信绑定到老账号（同 plan §二.3"原 H5 密码确认后绑定"），并自动切换登录态到老账号。
3. 冲突保护（不自动认定谁是正确账号，plan §二.4）：老账号已绑定其他微信 → 拒绝并提示"该手机号已绑定其他微信账号，请联系商家处理"；当前微信会员已产生业务数据（预约/会员卡/流水）→ 拒绝转绑并提示联系商家，绝不丢数据。
4. 转绑后当前自动新建的空壳会员（无任何业务数据）在**同一事务**内删除。

验收：
- [ ] 不撞号：填手机号直接成功，profile 生效
- [ ] 撞号+密码正确：openid 转到老账号、空壳删除、登录态切换、老账号手机号/数据不变
- [ ] 撞号+密码错误：明确报错不绑定
- [ ] 老账号已绑其他微信：拒绝并提示联系商家
- [ ] 空壳已有预约时：拒绝转绑
- [ ] 全程 openid 唯一不变量恒成立

## R5 小程序设置/重置 H5 密码 + admin 重置

1. 小程序「我的」新增"设置 H5 密码"：前提本会员已绑定手机号；设置/重置走同一端点（微信身份即凭证，plan §二.5）；密码 6~64 位。未绑手机号时入口引导先完善资料。
2. admin 会员管理新增"重置密码"（商家输入新密码，6~64 位）——"忘记密码联系商家"闭环的最后一段。
3. 未绑定微信的会员不能用微信重置（其小程序内根本无法登录该账号，天然满足）。

验收：
- [ ] 小程序设置密码后，H5 可用该手机号+密码登录
- [ ] admin 重置后旧密码失效、新密码可登录
- [ ] 无手机号的纯微信会员点设置密码被引导完善手机号

## R6 短信下线

1. 删除顾客端短信验证码登录能力（H5/小程序 UI 与调用全部移除）。
2. 服务端短信端点保留但受 `sms.mode` 约束：`dev` 可用（本地开发），**`off`（新增）一律拒绝**并提示"短信登录已下线，请升级小程序至最新版本"；生产配置必须 `off`（顺带关闭现状 dev 固定 123456 的任意登录漏洞）。
3. config/示例配置与部署 runbook 同步更新。

验收：
- [ ] dev 模式旧流程仍可跑通（供未升级小程序过渡）；off 模式两端点 4xx 且文案明确
- [ ] `config.example.yaml` / 部署文档含 `sms.mode: off` 说明

## 约束

- 冻结决策修订随本批落 AGENTS.md：D25 废除（微信首登直建号+密码认领），新增密码体系决策。
- 不动交易/预约/卡业务逻辑；appointment.member_id NOT NULL 不变（会员恒存在）。
- 存量无密码会员的迁移路径 = admin 重置 / 小程序微信绑定后自设，不提供批量导入密码。
