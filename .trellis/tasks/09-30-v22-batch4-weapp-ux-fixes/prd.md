# V2.2 第四批：预约资料弹层 UX 翻转 + 小程序登录/联调修复 + 全流程对抗式深测

## Goal

对齐用户实测反馈的三个问题（H5 预约资料弹层 UX、小程序登录链路、疑似旧包现象），并完成小程序端下单→核销全流程的深度对抗式审查与逻辑优化。

## 事实核对结论（规划前已逐项核实）

1. **H5 预约资料弹层（问题属实，修）**
   - 现状：BookingPage.vue:385 提交时资料不全弹 AppSheet——「去完善」是 primary 在上、「先跳过，继续预约」ghost 在下；点去完善存草稿跳 `/me/profile`，ProfilePage.save() 成功后**停留原页不回跳**（用户抱怨的核心）。
   - 修复：① 按钮翻转——**「立即预约」primary 在上（直接提交）**，去完善降级为下方弱化样式；② ProfilePage 感知"来自预约"（sessionStorage 草稿存在 = 回跳信号），保存成功后自动返回预约页，预约页既有草稿恢复逻辑（batch 1 已有）接住；③ 保存失败停留原页报错。
   - 语义细节：弹层里「立即预约」= 不去完善直接提交并置跳过标记（原"先跳过"语义，重新排序换文案）；去完善成功回跳后**不清跳过标记**——若资料补全了弹层自然不再出；未补全下次提交仍提醒。
2. **小程序登录（部分为环境/旧包问题，部分修）**
   - 代码事实：`pages/login` 已是**纯微信一键登录**（无手机号/验证码 UI）；tabBar 四项含「服务」（app.json：首页/服务/预约/我的）；输入框 48px 显式高度（v2.1.0 修复）都在当前代码里。用户看到"手机号+验证码界面、缺服务 tab、占位截断一半"三症同源 → **开发者工具跑的是旧版代码**（旧导入路径或缓存未清）。
   - 真环境问题：「点击登录显示连接不上 127.0.0.1」= devtools(Windows) → WSL loopback:8080，**后端没在本机跑**（或没监听 0.0.0.0 / WSL 镜像网络未配）。修复：config.js 支持不改代码覆盖 BASE_URL（storage 键 `anmo.base_url`）+ 核对/文档化一条命令的本地后端启动（scripts/start-anmo.sh 适配）+ README 联调章节（re-import 项目路径 `/mnt/Projects/Anmo/apps/weapp`、清缓存指引、D24 dev 兜底说明：无正式 appid 时 openid="dev:"+code 可跑通全流程）。
   - 短信登录移除是既定决策（D27，第二批已拍板"H5 切密码登录、短信下线"）——回复确认；是否恢复短信作备用交用户决策（默认不恢复）。
3. **全流程深测（用户要求）**
   - H5：真浏览器跑 注册/登录 → 预约（含资料弹层新交互）→ 我的预约 → 核销码 → 门店卡；admin 浏览器跑 预约→卡核销（新记录区块）→撤销→散客结算→标签管理→服务追踪。
   - weapp：单测全量 + 对抗式代码审查（登录态启动链路、401 重试、预约/取消/改期、claim 认领、H5 密码设置、核销码门槛、分享路径）——devtools CLI 不在 WSL，真机项列人工清单。
   - 顺带优化：审查中发现的逻辑 bug 一并修（小步、不扩范围），UI 细节（占位截断复查当前包）确认或修。
