
# Anmo 按摩店系统 V1 完整 Plan（最终版）

**账号体系 + 会员服务追踪 + 预约页交互 + 后台门店选点 + H5 地址兼容**  
**只讲产品需求、功能设计，不涉及接口和表结构。**

---

## 一、项目目标

本系统面向按摩店，解决五件事：

1. **账号统一**：小程序微信登录为主，H5 手机号+密码为辅，两端共用同一个 `user_id`。
2. **资料完善**：用户只填姓名、手机号，平时不打扰，预约时自然提醒，个人中心给进度。
3. **服务追踪**：技师核销时顺手记录实际调理部位、服务方式、备注，后台自动串成会员服务档案。
4. **预约体验**：预约页底部固定提交按钮，用户不用下滑就能提交。
5. **门店地址**：后台内置地图选点，H5 地址跳转全浏览器兼容。

核心原则：

> 用户少填，技师顺手记，后台自动串，商家好管理。  
> 不做医疗化表达，不做 AI 诊断，不做治疗方案。  
> 用户不可见内部标签和服务记录。

## 二、账号体系

### 1. 小程序登录

- 微信静默登录，获取 openid。
- 不设用户名、密码、验证码。
- 首次登录后可引导完善：**姓名 + 手机号**。
- 资料完善弹窗由商家后台控制，**默认关闭**。
- 开启后：
  - 首次登录且未完善资料的用户提示一次。
  - 已登录但尚未完善姓名/手机号的老用户也提示一次。
  - 已完善用户不再提示。
  - 用户拒绝或关闭后，不再重复弹出。
- 微信手机号快速验证属于收费能力，做成后台开关，**默认关闭**。
- 默认让用户手动填写手机号。

### 2. H5 登录

- 改为：**手机号 + 密码**注册/登录。
- 删除现有固定 `123456` 假验证码。
- 密码安全哈希保存。

### 3. 两端统一

- 内部 `user_id` 作为唯一用户主键。
- 微信 openid、手机号作为关联身份。
- H5 老用户进入小程序时，如果手机号已存在，通过原 H5 密码确认后绑定微信。
- 小程序用户以后需要使用 H5 时，在小程序“我的”里设置 H5 密码，然后即可用手机号+密码登录 H5。
- 不创建重复账号。

### 4. 手机号冲突处理

**小程序端：**
- 一个手机号原则上只能绑定一个 `user_id`。
- 已被绑定时，不允许第二个微信直接绑定，提示“该手机号已绑定其他账号，请联系商家处理”。
- **不自动认定谁是正确账号。**

**H5 端注册：**
- 若手机号已存在且已绑定微信，提示：“该手机号已开通微信账号，请前往小程序「我的」设置 H5 密码后登录”，不允许重复创建账号。

### 5. 密码重置规则

- 已绑定微信的用户，可以通过当前微信身份直接重置 H5 密码。
- 未绑定微信的用户，不能使用该方式重置。
- 路径：小程序“我的” → 重置 H5 密码 → 验证当前微信已绑定 → 设置新密码。
- 若用户忘记 H5 密码且无法通过微信重置，提示“请联系商家后台重置密码”。

### 6. 技师端账号体系

- 技师账号由商家后台统一创建。
- 账号为手机号，初始密码由后台设置。
- 技师端仅支持手机号+密码登录，不支持微信登录。
- 技师只能看到自己的核销记录，看不到全店会员档案。
- 商家可停用技师账号，停用后无法登录。

### 7. 解绑/注销

- V1 不提供用户自主解绑手机号、注销账号功能。
- 需联系商家后台处理。

## 三、用户端资料完善

### 1. 必填资料

用户端必填资料只有：
- 姓名
- 手机号

原则：

> 用户负责提供身份资料，服务资料由技师产生。

### 2. 首登弹窗（后台控制，默认关闭）

- 由商家后台控制开关，默认关闭，方便小程序过审。
- 开启后，首次登录且未完善资料的用户提示一次。
- 已完善用户不再提示。
- 用户拒绝或关闭后，不再重复弹出。

### 3. 个人中心进度条（默认开启）

- 位置：头像下方，一条很矮的提示条。
- 未完善时显示：

> 资料完善度 50%｜完善手机号，方便预约联系 [去完善]

- 已完善时：直接隐藏，或显示“资料已完善”。
- 规则：
  - 手机号 + 姓名两个字段，填一个算 50%，两个都填算 100%。
  - 点击“去完善”跳设置页填写。
  - 不弹窗、不挡操作，用户爱点不点。
  - 默认开启，不依赖后台弹窗开关。

### 4. 预约流程轻提示（默认开启）

- 用户点“立即预约”时，如果资料不完整，弹一个轻量半屏提示。
- 文案：

> 填写手机号，方便技师联系您确认预约。  
> [去完善]  [先跳过，继续预约]

- 规则：
  - 点“去完善” → 跳设置页 → 填完自动返回继续预约。
  - **跳转完善资料页时，保留当前预约页已选的所有信息；返回预约页后自动恢复选中状态，无需重新选择。**
  - 点“先跳过” → 继续预约，不拦着。
  - 每个用户只提示一次，跳过以后不再弹。
  - 已完善用户直接进预约，不弹。
  - 默认开启，不依赖后台弹窗开关。

### 5. 后台开关汇总

| 项目 | 默认 | 说明 |
|------|------|------|
| 首登弹窗 | 关闭 | 商家可开，只提醒一次，方便过审 |
| 个人中心进度条 | 开启 | 长期提醒，不打扰 |
| 预约半屏提示 | 开启 | 情境提醒，只一次 |

### 6. 不做

- 不送积分、不送优惠券。
- 不反复弹窗。
- 不在首屏强制授权。
- 不做预约时选填调理需求。

## 四、技师端：服务记录

位置：

> 技师完成核销/结算前

增加三个**选填项**：

### 1. 实际调理部位
- 多选，最多 3 个。
- 默认：肩颈、腰背、腿部、足底、全身、其他。

### 2. 服务方式
- 单选。
- 默认：按摩、针灸、拔罐、刮痧、艾灸、仪器、膏药、其他。

### 3. 技师备注
- 选填。
- V1 先做输入框 + 快捷填写。
- **快捷短语由商家后台在「服务标签管理」中统一配置**，如“力度适中”“重点放松肩颈”。
- 技师端点击即可快速填入备注框。
- 语音转文字放后续版本。
- 例如：“腰部左侧比上次紧，下次重点关注。”

全部选填，不填写也可以正常完成核销。

### 4. 散客核销规则

- 未预约直接到店的客人，核销时同样可以填这三个字段。
- **散客核销必须录入手机号**，系统自动匹配/创建会员档案，服务记录同步归档。
- 若商家选择不录手机号，仅能完成核销，不生成服务记录与会员档案。

### 5. 核销撤销规则

- 核销撤销时，对应服务记录同步标记作废/删除，不计入会员服务档案汇总。

### 6. 安全确认

- 核销页增加一个勾选：**服务前已完成沟通**。
- 建议强制勾选，默认不勾，技师点一下即可。
- 如用户有高血压、怀孕、心脏病、术后等情况，技师服务前口头确认。
- 不做“已确认无禁忌”等医疗化措辞，避免系统承担判断疾病的责任。

## 五、商家后台标签管理

新增：

> 系统设置 → 服务标签管理

分成两个独立标签组：

- 调理部位
- 服务方式

支持：

- 添加
- 停用
- 排序

**删除规则：**

- 停用 = 不再出现在新的核销页面。
- 删除 = 仅允许删除从未被使用的标签。
- 历史服务记录不受标签删除/停用影响。
- **已停用的标签，在历史记录筛选器中仍可见、可筛选，保证历史数据可查；仅核销录入页隐藏。**

现有“会员标签”系统继续保留，不与服务记录混淆。

核心区别：

> 会员标签 = 这个客户是什么类型  
> 服务标签 = 这次服务做了什么

商家后台添加的会员标签，用户不可见。  
服务记录同样属于商家内部数据，用户不可见。

## 七、小程序预约页面交互体验优化

### 1. 现状痛点

用户点击服务卡片进入预约页后，需依次选择服务、日期、具体时段。  
预约提交按钮固定在页面最底部，用户完成所有信息选择后，必须手动下滑页面才能找到提交按钮。  
多出无效操作步骤，打断预约操作连贯性，极易造成用户流失，降低预约转化率。

### 2. 优化目标

- 用户不用下滑就能提交。
- 页面更紧凑，核心选择项与操作区集中展示。
- 选完信息后按钮状态实时反馈，减少误操作。

### 3. 落地优化方案

**① 底部固定提交按钮**

- 将「立即预约 / 提交预约」按钮固定在页面底部悬浮常驻展示。
- 不受页面滚动影响。
- 用户任意操作页面、无需下滑，随时可查看并点击提交按钮。
- 必须适配 iPhone 底部安全区：留出 `safe-area-inset-bottom`，避免按钮被横条挡住。
- 页面内容区底部增加留白，避免最后一个选项被固定按钮盖住。

**② 按钮置灰与提示**

- 未选完服务 / 日期 / 时段时，按钮置灰不可点。
- 显示提示文案，如“请选择服务”“请选择日期”“请选择时段”。
- 选完后按钮变亮，可点击提交。

**③ 状态实时同步**

- 在按钮正上方显示一行小字，展示用户已选核心信息：

> 全身按摩 · 今日下午 3:00  
> [ 立即预约 ]

- **模糊预约场景**：未选具体时间时，显示：

> 按摩 · 今日下午 · 店家安排时间  
> [ 立即预约 ]

- 不把已选信息塞进按钮内部，避免按钮文案过长、视觉混乱。

**④ 精简页面排版**

- 优化预约页各项选择模块（服务、日期、时段）的间距、留白、字体样式。
- 压缩无效页面高度，让核心选择项与操作区集中展示。
- 页面视觉更紧凑整洁。

**⑤ 键盘弹起处理**

- 填写“备注”输入框时，键盘会弹起。
- V1 简单处理：底部固定按钮可被键盘遮挡；备注为选填项，不影响核心提交流程。

**⑥ 不做自动滚动**

- V1 不做“用户完成单项选择后页面自动轻微适配滚动”。
- 原因：不同屏幕高度不一致，自动滚动容易做成“用户没点它自己乱滚”。
- 底部固定按钮已经解决核心痛点，自动滚动属于体验增强，后续再评估。

**⑦ 埋点统计**

- 统计口径：**进入预约页 UV、点击提交按钮次数、提交成功次数、预约转化率**。
- 用于验证优化效果。

## 八、后台门店经纬度录入优化

### 1. 现状痛点

小程序后台新增/编辑门店信息时，经度、纬度为必填参数，但系统无自带坐标获取能力。  
管理员需手动跳出后台，打开高德地图网页版，搜索门店地址、点击分享，从链接参数中手动提取经纬度，再复制粘贴至后台表单。  
整体操作步骤繁琐、效率极低，多门店录入工作量巨大，且手动提取易出错，对操作人员有一定认知门槛。

### 2. 优化目标

在不产生任何费用、不使用付费接口、低开发量的前提下，将经纬度获取能力内置至后台门店表单。  
实现傻瓜式一键精准录入，无需跳转外部平台、无需手动解析链接参数。  
保证坐标与小程序业务体系完全适配、无偏移。

### 3. 最终落地方案：高德地图 JS API 免费版

**① 核心免费保障**

- 使用高德 JS Web API 免费版。
- 仅用于后台管理员内部录入操作，非 C 端大规模访问。
- 每日免费额度完全够用，永久不会产生计费、不会触发超限限制。
- 需提前申请 Key，并配置后台域名白名单。
- 若 Key 申请受限，可降级为手动输入经纬度。

**② 功能实现方式**

在后台门店信息表单新增「地图选点」按钮，点击弹出内嵌高德地图弹窗。

提供两种傻瓜式录入方式：

- **地址搜索回填**：输入门店完整地址，地图自动检索匹配点位。  
  搜索结果以列表展示，管理员从列表中选择正确结果。  
  点击对应结果后，系统自动将精准 lng、lat 回填至表单输入框。
- **手动拖拽选点**：直接拖拽地图标记定位门店精准位置。  
  拖拽后点击“确认选点”再回填，避免手滑拖错位置直接覆盖。
- **搜索无结果引导**：搜索无结果时，提示“未找到匹配地址，请拖拽地图手动选点”，引导用户使用拖拽模式。

**③ 技术优势**

- 所有地图渲染、地址检索、坐标拾取、数据回填操作均在前端浏览器完成。
- 不消耗后端接口配额，零服务器压力。
- 完全适配高德坐标系。
- 全系统统一使用 **GCJ-02** 坐标系，与小程序现有定位体系一致，无坐标偏移问题。

**④ 兼容兜底机制**

- 保留原有手动经纬度输入框。
- 若地图检索异常、网络波动等特殊情况，可手动录入坐标，保证功能不中断。
- 手动输入框增加范围校验：
  - 经度：73～135
  - 纬度：3～53
  - 超出范围提示“请输入正确的经纬度”。
- **手动输入经纬度时，自动保留6位小数，超出部分四舍五入。**

## 九、H5 门店地址浏览器兼容性优化

### 1. 现状痛点

小程序 H5 页面门店地址跳转功能存在严重浏览器兼容性问题，多设备、多浏览器表现不一致：

- PC 端浏览器、手机 EDGE 浏览器点击地址可正常跳转至高德地图，精准定位门店位置。
- Via 等主流移动端浏览器点击后跳转失效，仅展示北京默认高德地图空白预览页。
- 无法加载门店精准坐标、无法正常跳转定位，功能失效，影响用户地址查看与导航体验。

### 2. 优化目标

统一 H5 地址跳转逻辑，修复移动端小众浏览器兼容问题。  
适配全主流手机、电脑浏览器。  
保证所有用户点击门店地址后，均可正常跳转、精准定位门店位置。  
消除空白页、默认错位定位问题。

### 3. 落地优化方案

**① 跳转触发入口**

- 点击门店信息区域的地址文字 / 地址图标，触发地图跳转。

**② 替换官方标准跳转协议**

- 摒弃原有非标准分享链接跳转方式。
- 采用高德地图官方标准化 URI 跳转格式。
- 强制携带门店精准经纬度、门店名称参数。
- 从根源解决多浏览器适配异常问题。

**③ 增加环境判断与降级兜底**

- 前端新增运行环境识别逻辑，区分：
  - APP 内置环境
  - 手机浏览器
  - 电脑浏览器
- 优先适配对应跳转方式。
- 若跳转失败，自动兜底展示带精准坐标的高德 H5 静态页面。

## 十二、验收标准

### 账号体系

- 小程序微信登录成功，自动创建/识别 `user_id`。
- H5 手机号+密码可注册、登录。
- H5 老用户绑定微信时，若手机号已存在，通过原 H5 密码确认后绑定到同一 `user_id`。
- 小程序用户可在“我的”设置 H5 密码，并成功登录 H5。
- 手机号已被绑定时，第二个微信不能直接绑定，提示联系商家。
- H5 端注册时，若手机号已绑定微信，提示前往小程序设置 H5 密码，不允许重复创建。
- 已绑定微信用户可通过微信身份重置 H5 密码；未绑定用户不能。
- H5 老用户忘记密码，可通过联系商家后台重置。
- 技师账号由后台创建，手机号+密码登录，只能看自己的核销记录。
- V1 不提供自主解绑/注销。

### 用户端资料完善

- 首登弹窗默认关闭，开启后只提示一次。
- 个人中心进度条默认开启，填一个字段显示 50%，两个字段显示 100%。
- 预约时资料不完整弹半屏提示，每个用户只提示一次，跳过不拦。
- 跳转完善资料页返回后，预约页已选信息保留。
- 已完善用户不弹任何提示。

### 技师端服务记录

- 核销前可填实际调理部位、服务方式、技师备注。
- 全部选填，不填也能完成核销。
- 快捷短语由后台配置，技师点击填入。
- 散客核销必须录手机号才生成会员档案和服务记录。
- 核销撤销时，服务记录标记作废，不计入汇总。
- 服务前已完成沟通勾选可点，默认不勾。
- 服务记录自动进入会员档案。

### 商家后台标签管理

- 服务标签分“调理部位”“服务方式”两组。
- 支持添加、停用、排序。
- 删除仅允许删除未使用标签。
- 历史记录不受影响。
- 已停用标签在历史筛选器中仍可见、可筛选。
- 会员标签和服务标签不混淆。
- 用户不可见内部标签和服务记录。

### 会员详情服务追踪

- 按时间倒序展示服务记录。
- 技师备注与商家备注独立展示，各记录操作人与时间。
- 支持按部位、服务方式、时间筛选。
- 支持关键词搜索备注。
- 支持服务记录汇总。
- 不做治疗报告、下一阶段方案。

### 预约页优化

- 底部固定提交按钮，不随页面滚动。
- 适配 iPhone 底部安全区。
- 页面内容底部留白，不被按钮遮挡。
- 未选完时按钮置灰并提示。
- 按钮上方显示已选核心信息。
- 模糊预约场景显示“店家安排时间”。
- 键盘弹起时按钮可被遮挡。
- 不做自动滚动。
- 埋点统计进入预约页到提交成功的转化率。

### 后台经纬度录入

- 门店表单有“地图选点”按钮。
- 弹窗内可地址搜索，结果列表选择后回填。
- 搜索无结果时提示拖拽选点。
- 弹窗内可拖拽标记，点击确认后回填。
- 手动输入经纬度保留，有范围校验和6位小数限制。
- 全系统统一 GCJ-02 坐标系。
- 高德 Key 配置域名白名单。

### H5 地址兼容

- 点击地址文字/图标触发地图跳转。
- 使用高德官方标准 URI 跳转。
- 区分 APP 内置、手机浏览器、电脑浏览器。
- 跳转失败时展示内嵌 iframe 地图 + 文字地址 + 复制地址按钮。
- iframe 失败时降级为纯文字 + 复制地址按钮。
- 跳转前校验经纬度参数，异常时搜索门店完整地址文本。
- 至少覆盖微信内置、Safari、Chrome、EDGE、Via、QQ 浏览器、手机自带浏览器。
- 跳转失败记录 UA 和原因。

### 密码错误提示

- 密码错误时提示“密码错误，请重新输入”。
- 连续5次锁定15分钟（V1 可先不做）。

## 十三、最终原则

> 小程序尽量简单，用户只负责登录和基础资料。  
> 平时不打扰，预约时自然提醒，个人中心给进度。  
> 技师负责记录实际服务。  
> 商家后台负责管理标签和会员，系统自动把每次服务串成完整档案。  
> 预约页底部固定按钮，用户不用下滑。  
> 后台门店选点内置地图，管理员不用跳外部平台。  
> H5 地址全浏览器兼容，用户点哪都能导航。  
> 不做医疗化表达，不做 AI 诊断，不做治疗方案。  
> 用户不可见内部标签和服务记录。

**一句话：用户填不填都能用，技师顺手记两笔，后台自动串档案；预约不用下滑，选点不用跳外部，地址全浏览器能打开；全程不说“治疗”，只说“服务”。**
